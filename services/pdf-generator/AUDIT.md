# Аудит платформы перед модулем PDF

Дата: 29 октября 2026. Режим: только чтение, без изменения ядра.

## 1. Стек

Фронтенд: React 19, Vite 7, React Router 7. Интерфейс — одностраничный сайт и отдельная страница админки.

Бэкенд: Node.js. Каталог, заявки и клиенты читает модуль `data-core`. Чат читает `ai-core` и ходит в модель OpenAI. Локально запросы принимает PowerShell-сервер на порту 5190 и на каждый запрос запускает Node. В продакшене те же входы — функции Netlify.

Инфраструктура: Docker нет, Redis нет, отдельного PHP/Python/Go нет. База — один файл SQLite, без отдельного сервера СУБД. Фото лежат в папке `uploads/`, в базе хранится только путь.

## 2. Данные

База: `data/site.sqlite`, движок `node:sqlite`.

`products` — id, название, описание, цена, валюта, количество, тип (услуга/товар), путь к фото, флаг «показывать на сайте». Артикула, категории, оптовой цены и НДС нет. Идентификатор товара используется как артикул в документе.

`orders` — id, дата, источник (магазин / чат / контакты), статус, имя, телефон, email, комментарий, тема, канал, сумма, название. Адреса доставки и реквизитов компании нет.

`order_items` — строки заявки: товар, название, цена, валюта, количество. Связь с заявкой по `order_id`, при удалении заявки строки удаляются вместе с ней.

Клиенты не лежат отдельной таблицей. Карточка собирается из заявок с одним нормализованным телефоном.

Индексы: первичные ключи `products.id`, `orders.id` и пара (`order_id`, `position`) у строк. Отдельных индексов под отчёты нет. Для текущего объёма (единицы услуг и сотни заявок с лимитом выборки 500) этого достаточно, выборка по id идёт по первичному ключу.

Корзина в базу не пишется. Она лежит в `localStorage` браузера до оформления заявки. Переписка чата тоже не сохраняется: в базу попадает только оставленный контакт.

## 3. Интерфейс и доступ

Кнопки экспорта ставятся в уже существующую админку:

- вкладка «Товары» — каталог PDF;
- карточка на вкладке «Заказы» — счёт PDF (отдельной страницы заказа нет);
- карточка на вкладке «Клиенты» — карточка клиента PDF.

Ролей нет. Есть один пароль админки: сессия в `sessionStorage` и заголовок `x-admin-key` на чтении заявок. Каталог товаров публичный. Скачивание PDF закрыто тем же ключом, что и CRM.

## 4. Можно ли встроить PDF, не ломая ядро

Да. Модуль `services/pdf-generator` — отдельный процесс. Он открывает SQLite только на чтение и не вызывает код `data-core`, `ai-core` и локального сервера. В существующем интерфейсе добавлены только кнопки скачивания.

Чего в документах не будет, потому что этого нет в базе: БИН и расчётный счёт, адрес доставки, скидка, НДС, оптовая цена. В PDF эти поля явно помечены как «не ведётся», а итог равен сумме заявки.

Отдельная очередь Redis/BullMQ не подключается: в платформе нет Redis, а тяжёлый рендер и так вынесен в свой процесс и не блокирует сайт. Каталог кэшируется файлом и пересобирается, когда меняется файл базы.
