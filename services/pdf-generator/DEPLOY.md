# Как подключить модуль PDF

Модуль лежит в `services/pdf-generator` и не меняет сохранение товаров, корзины, заявок и чата.

## Запуск

Из папки `services/pdf-generator`:

```
npm install
npm start
```

Сервис слушает `http://127.0.0.1:5191`. Нужен Google Chrome (путь по умолчанию `C:\Program Files\Google\Chrome\Application\chrome.exe`). Другой браузер задаётся переменной `CHROME_PATH`.

Ключ скачивания — тот же, что у админки. Если у API задан `ADMIN_KEY`, передайте его и процессу PDF.

Кнопки уже стоят в админке: «Каталог PDF», «Счет PDF», «Карточка PDF». Они запрашивают этот сервис и сохраняют файл. Сайт и API при этом могут работать как раньше.

## Что отвечает сервис

- `GET /catalog.pdf` — прайс, альбомный A4, с обложкой и карточками.
- `GET /orders/{id}.pdf` — счёт по заявке, книжный A4.
- `GET /clients/{id}.pdf` — карточка клиента и его заявки.

Все три маршрута требуют заголовок `x-admin-key`. База открывается с флагом `readOnly`. Запись в SQLite этот процесс не делает.

Каталог кэшируется в `services/pdf-generator/.cache`. Папка служебная, в git её класть не нужно.

## Чего модуль специально не делает

Не правит `data-core`, `ai-core`, `server.ps1` и схему базы. Не ставит Redis. Не считает НДС и не придумывает реквизиты, которых нет в данных.
