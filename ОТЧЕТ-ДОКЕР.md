## 1. Цель

Упаковать работающий сайт в Docker, чтобы его можно было собрать и запустить одной командой на другом компьютере. Вместе с сайтом должны подниматься каталог, заказы, клиенты и админка. Данные не должны пропадать при перезапуске контейнера.

## 2. Что представляет собой проект

Это одностраничный сайт на React и Vite. Посетитель смотрит визитку, выбирает услуги и отправляет заявку. Администратор входит по паролю, правит каталог и ведёт заказы.

Данные хранятся не в браузере, а в одном файле SQLite:

| Таблица | Содержимое |
|---|---|
| `products` | каталог услуг и товаров |
| `orders` | заявки |
| `order_items` | строки заявки |
| `clients` | клиенты, один на номер телефона |
| `users` | админ и менеджер |
| `sessions` | сессии входа |

Цена заказа считается на сервере по каталогу. Браузер передаёт только идентификатор услуги и количество.

## 3. Почему понадобился отдельный сервер для контейнера

Локально API запускается скриптом `server.ps1`. Это сервер Windows PowerShell: он слушает порт и для каждого запроса вызывает Node. В обычном Linux-образе Docker такого сервера нет.

Логика базы уже написана на Node в папке `data-core` и не зависит от Windows. Для контейнера добавлен `docker/server.js`. Он принимает те же адреса, что и PowerShell-сервер, но работает на любой системе, где есть Node.js 22:

- `GET /api/products` — каталог;
- `POST /api/orders` — заявка;
- `POST /api/login` и `GET /api/session` — вход;
- `POST /api/upload` — фото администратора;
- `POST /api/chat` — чат, если задан ключ OpenAI;
- остальные адреса — собранный сайт, включая `/admin`.

## 4. Состав контейнера

Сборка в два шага.

1. Образ `node:22` ставит зависимости и выполняет `npm run build`. На выходе появляется папка `dist` с готовым сайтом.
2. Тонкий образ `node:22-bookworm-slim` забирает только сайт, `data-core`, `ai-core`, стартовый каталог и сервер. Исходники React и `node_modules` в рабочий образ не входят.

Секреты в образ не попадают. Файл `.env` указан в `.dockerignore`. Пароли и ключ чата передаются при запуске через `docker compose`.

Файл базы внутри контейнера: `/data/site.sqlite`. Новые фото пишутся в `/app/uploads`. Оба пути подключены как тома Docker:

- `site-data` — база;
- `site-uploads` — фото, загруженные из админки.

Фото, которые уже лежат в проекте, попадают в сборку сайта и открываются по адресу `/uploads/...`. Если администратор загрузит новое фото, оно сохранится в томе и не сотрётся при пересборке сайта.

Пустой том при первом запуске получает каталог из `data/products.json`. Уже существующие заказы в этот новый том сами не копируются: это отдельная чистая база контейнера.

## 5. Как запустить

Нужны Docker Desktop и открытый порт 8080.

```powershell
cd C:\Users\Arman\Desktop\projects\arman-vizitka
docker compose up --build
```

После сборки:

- сайт: http://127.0.0.1:8080/
- админка: http://127.0.0.1:8080/admin

Остановка: `Ctrl+C`, затем `docker compose down`. Тома при этом остаются. Команда `docker compose down -v` удаляет тома вместе с базой и загруженными фото.

Пароли админки задаются в `.env` переменными `ADMIN_PASSWORD` и `MANAGER_PASSWORD`. Без них каталог открывается, а вход в админку отвечает, что учётки ещё не настроены.

## 6. Как проверить

1. Открыть http://127.0.0.1:8080/ и убедиться, что видны услуги и цены.
2. Запросить http://127.0.0.1:8080/api/products — в ответе JSON с полем `products`.
3. Отправить заявку из корзины и увидеть её в админке.
4. Выполнить `docker compose restart` и убедиться, что заявка на месте.
5. Проверка живости контейнера сама ходит на `/api/products`.

На компьютере, где готовился отчёт, команда `docker` не установлена, поэтому образ здесь не собирался. Проверен сам сервер контейнера: Node запускает `docker/server.js`, каталог, главная страница и страница админки отвечают.

## 7. Что намеренно осталось снаружи

- Генератор PDF использует Chrome и остаётся отдельной программой на порту 5191. В контейнер сайта он не включён, чтобы образ не тащил браузер.
- Публикация на Netlify не заменяется контейнером. На Netlify база лежит в Blobs, в Docker — в томе.
- Чат молчит с кодом `no_key`, пока в окружении нет `OPENAI_API_KEY`.

## 8. Вывод

Сайт, каталог, заказы, клиенты и админка собираются в один контейнер командой `docker compose up --build`. Windows-часть заменена кроссплатформенным Node-сервером с теми же адресами API. База и новые фото вынесены в тома, поэтому перезапуск контейнера их не удаляет. Секреты остаются в `.env` на машине, где запускают контейнер, и не записываются в образ.
